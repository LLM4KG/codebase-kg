## What was run

The **52** candidates that `scripts/wp12_apply_loss_report.py` (M1) found had
at least one edit the applier would have accepted. Each was rebuilt with **only** those
edits — through `EditScript.to_json()`, so a reduction cannot differ from a real script
in serialisation — and sent through the unmodified `run_candidate`, the unmodified Node
applier and the unmodified images. The *input* changed; no code did.

All published candidates here graded `never_applied`. Every replay came back
`apply_mode = exact_unique`, so the Python mirror and the Node applier agreed on all
52 — which is the cross-check that licenses step 8's corpus-wide numbers.

**9 of 52** would have passed — so all-or-nothing discarded a
*working* fix in 9 cases and a broken one in 43. Partial correctness is mostly not
correctness, which is the result that keeps the published numbers usable.

## The bound this puts on WP12's matched totals

22 → 15 and 23 → 18. Because the applier is all-or-nothing, those figures are **upper
bounds on the damage a thin context did**. The counterfactual below says how much of

counterfactual is how much of it the applier chose.

Read the table as a whole, not one row at a time:

- **The floor arm does not move.** 0/30 on both legs under per-edit application too.
  Its `floor` candidates survive the applier only by creating a file and never wiring
  it in, and the replay confirms that is worth nothing. The most load-bearing number
  in WP5 is not an artifact of the applier.
- **Three of the four matched totals do not move at all.** For Claude BM25 (18) and both
  Qwen matched arms (15, 18), "upper bound on the damage" and "measurement of the
  damage" turn out to be the same number. The caveat WP12 shipped with narrows to one
  cell rather than applying to all four.
- **The exception is the cell that started this work.** Claude dense @matched goes
  15 → 20, entirely from P2, where all five candidates pass once the applier stops
  discarding a correct `note.ts` fix over edits to a file the context never held. That
  is Qwen's 5/5 on the identical context, reached by the identical edits.
- **It is not a baselines-only effect.** Everything that moved: Claude Sonnet 4.6/`text_emb_3_large_matched` +5, Qwen3-Coder/`whole_file` +2, Qwen3-Coder/`kg_augmented` +1, Qwen3-Coder/`bm25` +1. The oracle and the KG arm both gain on Qwen, so per-edit application is not a
  thumb on the scale for one side of the comparison.

## What this does not license

- **Changing the applier.** All-or-nothing is right for the harness and stays exactly
  as published; changing it would break WP5 comparability across every condition.
- **Reporting the counterfactual alone.** A per-edit applier accepts partial fixes, and
  a partial fix that happens to pass a behavioural test is not the same result as a
  complete one. The published number is the measurement.
- **Reading a per-cell counterfactual as significance.** n=5 per cell, temperature 0.
